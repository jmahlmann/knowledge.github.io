    Einstein Toolkit

    The Einstein Toolkit is a community-driven, open-source software platform for research in relativistic astrophysics and gravitational physics. It is built on the Cactus framework and bundles 270+ components ("thorns") covering spacetime evolution (McLachlan, Lean, Baikal), relativistic (magneto-)hydrodynamics (GRHydro, IllinoisGRMHD), initial data, analysis, and computational infrastructure, together with tools for simulation management and visualization. Useful upstream references: List of available thorns, documentation and tutorials.

    Einstein Toolkit on Dartmouth's Discovery Cluster¶

    We maintain a shared installation together with all dependencies in a Spack environment. Load it with:

    source /dartfs/rc/lab/E/EPaCO/activate-cactus.sh

    Besides putting the required compilers, MPI, and libraries in your environment, this script defines the following variables:

    Variable Purpose
    $ET_BASE_PATH Einstein Toolkit base directory — you manage simulations from here
    $ET_USER_THORNS_PATH User thorns used by the EPaCO group, especially the force-free MHD thorns
    $ET_SIMS_PATH Lab storage for simulation output

    Add it to your shell startup

    If you use the toolkit routinely, add the source line to your ~/.bashrc so the environment is always available on login.

    Simulation management¶

    All commands below are run from inside the base directory:

    cd $ET_BASE_PATH

    Simulations are driven by simfactory, the Einstein Toolkit's simulation factory. Group-specific thorns (in particular the force-free MHD thorns) live in $ET_USER_THORNS_PATH and are linked into arrangements/UserThorns.

    Running a simulation¶

    simfactory/bin/sim submit <SIMULATION_NAME> \
    --parfile=<PARAMETER_FILE.par> \
    --procs=<TOTAL_CORES> \
    --ppn=<CORES_PER_NODE> \
    --ppn-used=<CORES_PER_NODE_USED> \
    --num-threads=<OPENMP_THREADS_PER_MPI_RANK> \
    --num-smt=<SMT_THREADS_PER_CORE> \
    --walltime=<HH:MM:SS> \
    --machine discovery
    Placeholder Meaning
    <SIMULATION_NAME> Unique name for this run. A directory of this name is created under $ET_SIMS_PATH; it must not already exist. Use a descriptive, greppable convention, e.g. encoding the physical parameters of the run.
    <PARAMETER_FILE.par> Cactus parameter file defining the physics setup. Group parameter files typically live under $ET_USER_THORNS_PATH/<THORN>/par/.
    <TOTAL_CORES> Total number of cores requested. Combined with --ppn this fixes the node count (nodes = procs / ppn).
    <CORES_PER_NODE> Physical cores available per node on the target partition.
    <CORES_PER_NODE_USED> Cores actually used per node — set below --ppn to leave cores idle (e.g. for extra memory bandwidth per rank).
    <OPENMP_THREADS_PER_MPI_RANK> OpenMP threads per MPI rank. 1 = pure MPI; larger values give a hybrid MPI/OpenMP layout with ppn-used / num-threads ranks per node.
    <SMT_THREADS_PER_CORE> Hardware threads (hyperthreads) used per core; 1 disables SMT.
    <HH:MM:SS> Requested wall time. Runs are checkpointed and can be resubmitted to continue beyond the queue limit.
    --machine discovery Selects the Discovery machine configuration in simfactory (queue, submit command, MPI launcher, …).

    Concrete example

    simfactory/bin/sim submit TEST \
    --parfile=$ET_USER_THORNS_PATH/FFOrtho/par/FFOrtho_Dipole_Glitch_2D.par \
    --procs=32 --ppn=32 --ppn-used=32 \
    --num-threads=1 --num-smt=1 \
    --walltime=24:00:00 \
    --machine discovery
    A single 32-core node, pure MPI (32 ranks), 24 hours of wall time.

    Following simulation output¶

    simfactory/bin/sim show-output --follow <SIMULATION_NAME> --machine discovery

    Streams the standard output of the run (like tail -f). Drop --follow to dump the log once and exit.

    Deleting a simulation¶

    simfactory/bin/sim purge <SIMULATION_NAME> --machine discovery

    Moves the simulation directory out of the simulation store into the simfactory trash.

    Warning

    purge removes the run from the active simulation directory. Make sure any output you still need has been copied elsewhere before purging, and double-check the simulation name.

    Other useful commands¶

    simfactory/bin/sim list-simulations   --machine discovery # all known simulations and their status
simfactory/bin/sim submit <NAME> --machine discovery      # resubmit / continue from checkpoint
simfactory/bin/sim stop <NAME>  --machine discovery       # cancel a queued or running job
